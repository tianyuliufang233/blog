## openEuler 22重启后，docker网络丢失，docker-compose up -d network not found
原因：由于docker daemon状态无法及时刷新到磁盘，导致重启后docker daemon状态不正常。  
解决方式：在/etc/sysconfig/docker文件中加入DISABLE_CRASH_FILES_DELETE=true  
参考：  
[系统掉电影响](https://docs.openeuler.org/zh/docs/22.03_LTS_SP1/docs/Container/%E5%AE%89%E8%A3%85%E9%85%8D%E7%BD%AE-3.html#%E7%B3%BB%E7%BB%9F%E6%8E%89%E7%94%B5%E5%BD%B1%E5%93%8D)
[openEuler network not found](https://blog.csdn.net/hotcoffie/article/details/130457800)

## openEuler 20.3升级到22.03
```

dnf clean all
dnf -y --releasever='22.03LTS_SP3' --allowerasing --setopt=deltarpm=false distro-sync --nogpgcheck

grub2-mkconfig -o /boot/grub2/grub.cfg

reboot
dnf remove kernel-4.1* -y
```

## k8s calico  报 “Unable to create token for CNI kubeconfig error=Post”
原因：kube-proxy 未正常启动  
参考：[Unable to create token for CNI kubeconfig error=Post](https://github.com/projectcalico/calico/issues/7529)  
[container install-cni (init) in calico pod Unable to create token for CNI kubeconfig error=Post dial tcp 10.233.0.1:443: i/o timeout](https://github.com/orgs/projectcalico/discussions/9205)  

## node无法加入集群，报已加入的节点不能修改为现有节点node name
原因：kubelet加入集群读取错误的hostname，生成的kubelet证书cn名hostname不一致  
临时处理：[kubelet.service 中加入--hostname-override直接指定node name](https://kubernetes.io/zh-cn/docs/reference/command-line-tools-reference/kubelet/)

## 使用kubectl连接kube-apiserver报错：“The connection to the server localhost:8080 was refused - did you specify the right host or port?”
原因：未执行kubectl config use-context kubernetes --kubeconfig=kube.config 
解决方式： 执行kubectl config use-context kubernetes --kubeconfig=kube.config
参考：[kubectl命令出现错误“The connection to the server localhost:8080 was refused](https://blog.csdn.net/lisongyue123/article/details/109643218)

## openvpn 连接kubernetes-pod网络
```
# 10.106.0.0/16为vpn网段，tunl0为pod网络，经过input后直接通过calico的tunl0转发了，所以eth0的MASQUERADE没有起作用。
iptables -t nat -A POSTROUTING -s 10.100.0.0/16 -o tunl0 -j MASQUERADE
# openvpn 转发伪装
iptables -t nat -A POSTROUTING -s 10.100.0.0/16 -o eth0 -j MASQUERADE
```
